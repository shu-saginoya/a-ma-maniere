# A ma maniere Webサイト リニューアル 作業計画書

本書は [SPEC.md](./SPEC.md) の内容を実現するための作業手順を、環境構築から本番公開までフェーズ順に整理したものです。

## 進め方の前提

- コーディング・実装作業は担当者（Copilot）が中心に行い、必要な確認事項が出た時点でユーザーに質問する
- 各フェーズは基本的に順番に進めるが、フェーズ3（サイト実装）とフェーズ0（情報確定）は並行して進める部分がある
- 正式な店舗情報・料金・SNS URL・画像等は、該当する実装箇所に着手するタイミングで都度確認する
- ドメイン移行は最もリスクが高い工程のため、既存メール（同ドメインのメールアドレス）が存在するかを事前に必ず確認する

## フェーズ0: 情報・素材の整理

現行サイト（WordPress）の内容をもとに、移行対象の情報を確定する。

- [ ] 店舗情報（店舗名・住所・電話番号・営業時間・定休日）の最終確認
- [ ] 料金表の最終確認（現行サイト `/price/` の内容踏襲）
- [ ] 店主紹介文（現行サイト `/introduction/` の内容踏襲、新サイトでは `/about/`）
- [ ] 使用する店舗写真・外観写真・作業風景写真の洗い出し
- [ ] Googleフォームの作成（現行の独自問い合わせフォームの項目を踏襲）
- [ ] LINE公式アカウントURLの確認（現行サイトに掲載あり: `https://lin.ee/9FP7AwS`。変更がないか確認）
- [ ] Instagram / Facebook の正式URLの確認
- [ ] Googleマップの店舗ピン確認（埋め込みかリンクかはフェーズ3のデザイン検討時に決定）
- [ ] 現行ドメインのメール利用有無の確認（**重要**。同ドメインでメールアドレスを利用している場合、DNS移行時にMXレコードを引き継ぐ必要がある）
- [ ] 現行ドメインの登録事業者・契約状況の確認（Cloudflare Registrarへの移管を検討するかの判断材料）

## フェーズ6: ドメイン・DNS移行準備

現行サイトを止めずに準備を進める工程。

- [ ] 現行ドメインのDNSレコード（A/CNAME/MX/TXT等）を事前にすべて控える
- [ ] メール利用がある場合、MXレコード・SPF/DKIM等のレコードを移行後も維持する計画を立てる
- [ ] Cloudflareにドメインを追加し、ネームサーバー変更前に設定内容を検証（Cloudflare側でDNSレコードを事前設定）
- [ ] 旧URLから新URLへの301リダイレクト方針を確定（例: `/introduction/` → `/about/`）
- [ ] SSL/TLS設定の確認（Cloudflare Universal SSL）
- [ ] ドメイン管理事業者からCloudflare Registrarへの移管要否を判断（必須ではない。移管しない場合はネームサーバーのみCloudflareへ向ける）

## フェーズ7: 本番切り替え

**このフェーズから現行サイトへの影響が発生するため、事前にユーザーへ切り替え日時を確認する。**

- [ ] Cloudflare Pagesにカスタムドメイン（`a-ma-maniere.jp`）を追加
- [ ] ネームサーバーをCloudflareへ切り替え（またはCloudflare経由でDNSレコードを向ける）
- [ ] DNS浸透確認（反映まで時間がかかる場合がある旨を事前共有）
- [ ] 301リダイレクトの動作確認
- [ ] メール送受信の動作確認（メール利用がある場合）
- [ ] 本番ドメインでのSSL証明書発行確認
- [ ] Google Search Consoleでの新URL確認・サイトマップ送信
- [ ] Googleビジネスプロフィールの情報とサイト内容の整合確認

- [ ] 軽微な修正対応

## リスクと対応方針

| リスク                                  | 対応                                                                           |
| --------------------------------------- | ------------------------------------------------------------------------------ |
| ドメイン移行時にメールが届かなくなる    | 移行前にMXレコード等を必ず控え、移行後すぐに検証する                           |
| DNS切替中に一時的にサイトが表示されない | 反映に時間がかかる可能性を事前に共有し、旧サーバーは切替後もすぐには解約しない |
| SEO評価の低下                           | 301リダイレクトを設定し、タイトル・見出し構造を可能な範囲で踏襲する            |
| SNS埋め込みによる表示不安定化           | SNS連携が失敗してもサイト本体表示に影響しない設計とする（SPEC.md 6.1節）       |
