# A ma maniere Webサイト リニューアル 作業計画書

本書は [SPEC.md](./SPEC.md) の内容を実現するための作業手順を、環境構築から本番公開までフェーズ順に整理したものです。

## 進め方の前提

- コーディング・実装作業は担当者（Copilot）が中心に行い、必要な確認事項が出た時点でユーザーに質問する
- 各フェーズは基本的に順番に進めるが、フェーズ3（サイト実装）とフェーズ0（情報確定）は並行して進める部分がある
- 正式な店舗情報・料金・SNS URL・画像等は、該当する実装箇所に着手するタイミングで都度確認する
- ドメイン移行は最もリスクが高い工程のため、既存メール（同ドメインのメールアドレス）が存在するかを事前に必ず確認する

## フェーズ6: ドメイン・DNS移行準備

現行サイトを止めずに準備を進める工程。

- [ ] 現行ドメインのDNSレコード（A/CNAME/MX/TXT等）を事前にすべて控える
- [x] メール利用がないことを確認（MXレコード等のメール移行は不要）
- [ ] Cloudflareにドメインを追加し、ネームサーバー変更前に設定内容を検証（Cloudflare側でDNSレコードを事前設定）
- [ ] 旧URLから新URLへの301リダイレクト方針を確定（例: `/introduction/` → `/about/`）
- [ ] SSL/TLS設定の確認（Cloudflare Universal SSL）
- [ ] ドメイン管理事業者からCloudflare Registrarへの移管要否を判断（必須ではない。移管しない場合はネームサーバーのみCloudflareへ向ける）

## リスクと対応方針

| リスク                                  | 対応                                                                           |
| --------------------------------------- | ------------------------------------------------------------------------------ |
| ドメイン移行時にメールが届かなくなる    | 移行前にMXレコード等を必ず控え、移行後すぐに検証する                           |
| DNS切替中に一時的にサイトが表示されない | 反映に時間がかかる可能性を事前に共有し、旧サーバーは切替後もすぐには解約しない |
| SEO評価の低下                           | 301リダイレクトを設定し、タイトル・見出し構造を可能な範囲で踏襲する            |
| SNS埋め込みによる表示不安定化           | SNS連携が失敗してもサイト本体表示に影響しない設計とする（SPEC.md 6.1節）       |
